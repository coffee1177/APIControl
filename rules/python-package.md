# Python 包与缓存规范

## `__pycache__`

- `__pycache__` 是 Python 自动生成的字节码缓存，不是项目源码，也不是运行前置文件。
- 不得手动创建、提交或保留仓库内的 `__pycache__` 目录及 `*.pyc`、`*.pyo` 文件。
- 本地检查产生缓存后可以直接删除；后续运行 Python 时重新生成属于正常行为。
- `.gitignore` 必须持续包含 `__pycache__/` 和 `*.py[cod]`。

## `__init__.py`

- 不为“看起来像 Python 包”而机械创建空的 `__init__.py`。
- 仅在文件承担实际职责时保留，例如：
  - 统一导出公共对象；
  - 执行明确且必要的包初始化；
  - 注册插件、模型或路由；
  - 兼容明确要求传统包结构的工具。
- 只有说明字符串、空内容或注释的 `__init__.py` 视为不重要，应删除。
- 删除前必须确认没有代码依赖该文件的导出或初始化副作用，并执行导入检查或相关测试。
- 当前 `backend/app/models/__init__.py` 负责集中导出 SQLAlchemy 模型，必须保留；如果以后改为直接从模型模块导入，可以在验证后删除。
