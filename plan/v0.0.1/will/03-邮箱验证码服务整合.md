# 需求三：邮箱验证码服务整合

## 一、需求目标

将已购买的邮箱登录验证码接收服务接入 APIControl，在统一页面查询可用邮箱、查看验证码消息并管理使用记录。

## 二、计划功能

- 配置服务商名称、接口地址和访问凭据。
- 查询并展示账户余额和服务状态。
- 获取或选择可用邮箱，展示邮箱地址、有效期和状态。
- 按发件人、主题或时间筛选验证码消息。
- 提取并展示验证码，同时保留查看原始消息的入口。
- 支持手动刷新或按合理间隔轮询新消息。
- 保存必要的邮箱申请记录、消息状态和费用信息。
- 对邮箱失效、消息延迟、请求超时和服务商限流给出明确提示。

## 三、安全要求

- API 密钥和邮箱访问凭据只保存在服务端，并采用加密存储。
- 页面仅展示脱敏后的凭据信息。
- 默认不在普通日志中记录完整邮件正文、完整验证码或访问令牌。
- 设置验证码和消息内容的保留期限，并允许用户主动删除。
- 接入和使用必须符合服务商条款及适用法律，不提供绕过平台风控或未经授权访问邮箱的能力。

## 四、接入前需要补充的信息

- 服务商名称及官方 API 文档。
- 鉴权方式、接口地址和测试环境。
- 邮箱的获取方式、有效期和计费方式。
- 消息列表、消息详情和验证码获取的接口规则。
- 请求频率限制、消息延迟范围和异常状态定义。

## 五、验收方向

- 能安全保存并验证一组服务商凭据。
- 能查询账户余额和可用邮箱。
- 能完成一次邮箱获取、消息刷新和验证码读取的完整流程。
- 服务商异常时，控制台能展示可理解的错误，不泄露敏感信息。
- 每次关键操作都能在使用记录中追踪。

> 本需求在“网址留存”和短信服务接入流程稳定后，再根据实际服务商 API 细化。
