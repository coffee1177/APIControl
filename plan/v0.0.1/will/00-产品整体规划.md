# APIControl 产品整体规划

## 一、产品背景

目前存在两类需要长期管理的信息：

1. 经常使用的网址。浏览器收藏夹受具体浏览器和设备限制，也不便于按照自己的方式进行展示和整理。
2. 已购买的第三方 API 服务，例如短信手机号验证码服务、邮箱登录验证码接收服务。不同平台的入口、余额、调用方式和使用记录比较分散。

APIControl 将以开源网站项目的形式提供一个个人控制台，先实现网址留存，再逐步接入不同类型的 API 服务。

## 二、产品定位

- 开源项目：源代码公开，允许使用者自行部署和修改。
- 网站形式：通过浏览器访问，不开发原生桌面端或移动端。
- 个人使用：第一版不设计注册、登录、多用户和权限体系。
- 本地存储：使用本地数据库保存数据，不依赖外部云数据库。
- 简单优先：第一版只实现明确需要的核心功能，不提前加入扩展功能。

## 三、阶段划分

### 第一阶段：网址留存

完成网址的新增、查询、编辑、删除、最多两级分类以及 JSON 导出，形成最小可用版本。

详细需求见 [01-网址留存.md](./01-网址留存.md)。

### 第二阶段：短信验证码服务整合

接入一个已购买的短信验证码服务，验证第三方 API 接入、密钥管理、余额查询、号码申请和验证码获取的完整流程。

详细需求见 [02-短信验证码服务整合.md](./02-短信验证码服务整合.md)。

### 第三阶段：邮箱验证码服务整合

接入一个已购买的邮箱验证码服务，提供邮箱账号查询、验证码读取和使用记录管理。

详细需求见 [03-邮箱验证码服务整合.md](./03-邮箱验证码服务整合.md)。

### 第四阶段：统一控制台

在前述能力稳定后，再规划统一仪表盘、服务状态、余额提醒、调用统计、操作日志和更多服务商适配能力。

## 四、初步信息架构

- 首页概览
- 网址库
- API 服务
  - 短信验证码
  - 邮箱验证码
- 使用记录
- 设置
  - 数据导出
  - API 凭据管理

## 五、暂不纳入 v0.0.1

- 注册、登录和用户体系。
- 团队协作和多人权限。
- 对外开放 APIControl 自身的公共 API。
- 自动调用任意未知第三方 API 的通用编排器。
- 浏览器插件和移动端原生应用。
- 复杂的数据分析和费用预测。

以上内容可在网址留存和首个第三方服务接入稳定后重新评估。
