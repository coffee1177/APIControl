# 需求一：网址留存

## 一、需求目标

将网址留存功能做成一个可在浏览器中访问的网站。项目采用开源方式发布，第一版面向个人使用，通过本地数据库保存网址，并支持将全部网址数据导出为 JSON 文件。

## 二、第一版定位

- 展示形式：网站。
- 项目性质：开源项目。
- 使用对象：个人使用，暂不提供注册、登录、多用户和权限功能。
- 数据存储：本地数据库，建议第一版使用 SQLite。
- 功能原则：只完成网址的增删改查、两级分类和 JSON 导出。

## 三、第一版功能范围

### 3.1 网址管理

- 新增网址：填写网址名称、URL、简介和所属分类。
- 查询网址：在网站页面中查看已经保存的网址。
- 编辑网址：修改网址名称、URL、简介和所属分类。
- 删除网址：删除前进行确认。
- 访问网址：点击网址后在浏览器中打开目标页面。

### 3.2 分类管理

- 支持一级分类和二级分类。
- 二级分类只能归属于一个一级分类。
- 分类层级最多为两级，不允许创建三级分类。
- 支持分类的新增、查看、重命名和删除。
- 网址可以归入一级分类或二级分类，也可以暂不分类。
- 删除存在网址或子分类的分类时必须先给出明确提示，避免数据归属不清。

### 3.3 JSON 导出

- 支持将本地数据库中的全部网址和分类导出为一个 JSON 文件。
- JSON 中保留网址、分类关系、创建时间和更新时间。
- 导出的数据结构需要包含格式版本号，为以后增加 JSON 导入能力保留兼容空间。
- 第一版只要求导出，不实现 JSON 导入和定期备份。

### 3.4 明确不做

- 不做注册、登录、多用户和权限管理。
- 不做标签、搜索、筛选、排序、置顶和访问次数统计。
- 不做浏览器书签导入和 JSON 导入。
- 不做云数据库、云同步和自动备份。
- 不做浏览器插件和移动端应用。

## 四、页面规划

### 4.1 网址展示页

- 分类区域：展示一级分类和二级分类。
- 网址区域：按照选中的分类展示网址名称、URL 和简介。
- 页面操作：新增网址、编辑网址、删除网址和导出 JSON。

### 4.2 新增或编辑网址

- URL：必填。
- 名称：必填。
- 简介：选填。
- 分类：选填。

### 4.3 分类管理

- 新增一级分类。
- 在一级分类下新增二级分类。
- 重命名或删除已有分类。
- 界面中不提供创建三级分类的入口。

## 五、建议数据对象

### 网址

- `id`：唯一标识。
- `title`：网址名称。
- `url`：完整链接。
- `description`：简介。
- `categoryId`：所属分类，可为空。
- `createdAt`：创建时间。
- `updatedAt`：更新时间。

### 分类

- `id`：唯一标识。
- `name`：分类名称。
- `parentId`：上级分类；一级分类为空，二级分类指向一级分类。
- `createdAt`：创建时间。
- `updatedAt`：更新时间。

## 六、JSON 导出结构建议

```json
{
  "version": "1.0",
  "exportedAt": "2026-08-07T00:00:00.000Z",
  "categories": [],
  "bookmarks": []
}
```

第一版只固定顶层结构，具体字段在数据表设计完成后保持一致。

## 七、第一版验收标准

- 能完成网址的新增、查看、编辑和删除。
- 网址数据保存在本地数据库中，网站重新启动后数据仍然存在。
- 能创建一级和二级分类，但不能创建三级分类。
- 网址能够归入指定分类，并在对应分类下展示。
- 能将全部网址和分类导出为结构清晰的 JSON 文件。
- 非法 URL、无效操作和删除确认均有明确提示。
- 项目不依赖外部云数据库即可在本地运行。

## 八、实现前待确认

- 前端和后端采用的具体技术栈。
- 网址采用列表、卡片还是其他视觉形式展示。
- 开源许可证类型。
- 删除分类时，分类内网址是禁止删除、变为未分类，还是同时删除。
