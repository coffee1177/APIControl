# 需求二：短信验证码服务整合

## 一、需求目标

将已购买的短信手机号验证码服务接入 APIControl，在统一页面完成服务配置、余额查看、手机号申请、验证码获取和使用记录查询。

## 二、计划功能

- 配置服务商名称、接口地址和访问凭据。
- 查询并展示账户余额和服务状态。
- 按国家或地区、项目、运营商等条件申请手机号，具体条件以服务商 API 为准。
- 展示已申请号码、有效期和当前状态。
- 手动刷新或按合理间隔轮询验证码。
- 支持释放号码、取消订单或重新获取，具体能力以服务商 API 为准。
- 保存必要的操作记录、订单标识和费用信息。
- 对余额不足、号码不可用、请求超时和服务商限流给出明确提示。

## 三、安全要求

- API 密钥只保存在服务端，并采用加密存储。
- 页面仅展示脱敏后的凭据信息。
- 日志中不得记录完整密钥、完整验证码或其他不必要的敏感数据。
- 所有申请、释放和配置修改操作需要记录操作时间与结果。
- 接入和使用必须符合服务商条款及适用法律，不提供绕过平台风控或批量滥用能力。

## 四、接入前需要补充的信息

- 服务商名称及官方 API 文档。
- 鉴权方式、接口地址和测试环境。
- 已购买的产品类型、支持地区与计费方式。
- 号码申请、验证码查询、号码释放的接口规则。
- 请求频率限制、订单有效期和异常状态定义。

## 五、验收方向

- 能安全保存并验证一组服务商凭据。
- 能查询账户余额。
- 能完成一次号码申请、验证码查询和号码释放的完整流程。
- 服务商异常时，控制台能展示可理解的错误，不泄露敏感信息。
- 每次关键操作都能在使用记录中追踪。

> 本需求在“网址留存”第一版完成后再细化接口和页面设计。
