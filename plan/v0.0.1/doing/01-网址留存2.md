# 01 网址留存：状态 2（列表接口设计）

## 一、本阶段目标

分类模块已经完成，接下来进入网址列表模块的设计。

本阶段先把“网址列表怎么查、怎么增删改、前后端怎么对接”定下来，不先展开实现代码。

## 二、设计原则

1. 只围绕网址列表和基础 CRUD 展开，不新增搜索、标签、排序、置顶、访问统计等能力。
2. 列表接口统一使用分页返回结构：

```json
{
  "items": [],
  "page": 1,
  "size": 20,
  "total": 0
}
```

3. 后端接口继续放在 `backend/app/api/web` 下面，网址模块统一使用 `list` 路由，不使用 `v1` 目录。
4. 分类信息直接复用现有 `/web/categories` 接口，列表页只负责展示和维护网址数据。

## 三、建议数据对象

### 3.1 网址表：`web-list`

建议先按下面这组字段设计：

| 字段名 | 含义 | 说明 |
| --- | --- | --- |
| `id` | 唯一标识 | 主键，自增 |
| `title` | 网址名称 | 必填 |
| `url` | 完整链接 | 必填 |
| `description` | 简介 | 选填 |
| `categoryId` | 所属分类 | 可为空，指向 `web-categories.id` |
| `createdAt` | 创建时间 | 必填 |
| `updatedAt` | 更新时间 | 必填 |

### 3.2 列表返回项

列表接口建议在基础字段外，额外返回一个展示用的 `categoryName`，方便前端直接渲染，不必再自己去树里找名称。

## 四、接口设计

### 4.1 查询网址列表

`GET /web/list`

#### 查询参数

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `page` | number | `1` | 当前页 |
| `size` | number | `20` | 每页条数 |
| `categoryId` | number \| null | 空 | 当前浏览的分类，可选 |
| `isAll` | boolean | `false` | 是否显示全部网站（包含分类和未分类） |

#### 返回结构

```json
{
  "items": [
    {
      "id": 1,
      "title": "FastAPI",
      "url": "https://fastapi.tiangolo.com/",
      "description": "Python Web 框架",
      "categoryId": 2,
      "categoryName": "后端工具"
    }
  ],
  "page": 1,
  "size": 20,
  "total": 1
}
```

#### 说明

- `isAll=true` 时直接查看全部网站，不再按分类过滤。
- `isAll=false` 时按 `categoryId` 过滤；如果不传 `categoryId`，默认只看未分类网站。

### 4.2 新增网址

`POST /web/list`

#### 请求体

```json
{
  "title": "FastAPI",
  "url": "https://fastapi.tiangolo.com/",
  "description": "Python Web 框架",
  "categoryId": 2
}
```

#### 规则

- `title` 必填。
- `url` 必填。
- `description` 选填。
- `categoryId` 选填，可以为空。
- 如果传了 `categoryId`，后端需要确认分类存在。

### 4.3 修改网址

`PUT /web/list/{id}`

#### 请求体

```json
{
  "title": "FastAPI",
  "url": "https://fastapi.tiangolo.com/",
  "description": "Python Web 框架",
  "categoryId": 2
}
```

#### 规则

- 支持修改名称、链接、简介和分类。
- 如果分类改为空，则表示移出分类。

### 4.4 删除网址

`DELETE /web/list/{id}`

#### 说明

- 删除前由前端做二次确认。
- 后端直接删除单条网址记录即可。

## 五、前端对接建议

1. 左侧继续使用现有分类树接口：`GET /web/categories`。
2. 右侧网址列表统一走 `GET /web/list`。
3. 新增、编辑、删除共用同一套表单字段。
4. 页面上先不做复杂搜索和排序，先把列表浏览和分类归属跑通。

## 六、待确认问题

1. 列表默认是“全部网址”，还是进入页面后直接看“未分类”。
2. 是否允许同一个 URL 出现多条记录。
3. `description` 是否需要限制最大长度。
4. 当前阶段是否把 JSON 导出接口一起并入列表模块。
