# 01 项目构造：状态 0

## 一、阶段目标

搭建 APIControl 的最小前后端项目骨架，完成前后端启动、测试接口和一个可点击验证的页面。本阶段只验证项目结构与联通性，不实现网址留存业务。

## 二、后端计划

### 2.1 技术与目录

- 使用 FastAPI。
- 按路由划分目录，接口放在 `backend/app/api/<业务名>/router.py`。
- 保留应用入口、配置、数据库和测试目录的清晰边界。
- 第一阶段先不建立网址、分类等业务表。

### 2.2 测试接口

- 新增健康检查接口，例如 `GET /health`。
- 成功时返回 JSON：

```json
{
  "success": true,
  "message": "APIControl 后端运行正常"
}
```

- 为测试接口编写最小接口测试，验证状态码和响应结构。

## 三、前端计划

### 3.1 基础依赖

- React。
- Axios。
- Ant Design。
- React Router。

### 3.2 路由配置

- 路由配置使用 JSON 兼容的数据结构，整体格式参考 `opcproduct/front/src/router/config.tsx` 的路由数组。
- 配置字段至少包括：`path`、`label`、`navigation` 和页面标识。
- JSON 只保存路径和页面元数据；页面组件通过页面标识映射，避免把组件逻辑写入 JSON。
- 页面路由与导航菜单从同一份配置生成，避免重复维护。

### 3.3 测试页面

- 新增一个测试页面，并注册到路由配置。
- 页面中放置一个 Ant Design Button。
- 点击按钮后通过前端 API 封装调用后端 `GET /health`。
- 请求成功后使用 `console.log` 输出后端响应。
- 请求失败时在页面给出简单错误提示。
- 除测试按钮和必要页面结构外，不增加其他业务页面或复杂样式。

## 四、实施顺序

1. 确认现有 `backend` 和 `fronted` 的实际入口、依赖管理和启动方式。
2. 初始化 FastAPI 应用及路由式目录，接入 `/health` 测试接口。
3. 初始化 React 页面及 Axios、Ant Design、React Router 依赖。
4. 建立 JSON 兼容的路由配置和页面映射。
5. 创建测试页面、按钮和后端请求封装。
6. 分别启动前后端，验证按钮点击后能在浏览器控制台打印成功响应。

## 五、本阶段验收标准

- 后端可以本地启动，`GET /health` 返回约定 JSON。
- 后端测试接口检查通过。
- 前端可以本地启动并显示测试页面。
- 页面使用 Ant Design Button，点击后实际调用后端接口。
- 成功响应会输出到浏览器 `console.log`，失败时页面有基本反馈。
- 路由配置为 JSON 兼容结构，并可生成页面路由和导航。
- 本阶段不加入网址留存之外的新业务功能。
