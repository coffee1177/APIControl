# 01 网址留存：状态 3（前端页面实现）

## 一、本阶段目标

在现有分类与网址列表接口基础上，实现“网站留存”第一版前端页面，完成分类浏览、网址分页展示、网址增删改、分类管理和 JSON 导出。

## 二、页面方案

1. 页面采用“分类导航 + 网址列表”的左右分栏结构。
2. 默认展示全部网址，并提供未分类及两级分类入口。
3. 网址使用紧凑列表展示名称、完整 URL、简介、分类和更新时间。
4. 新增、编辑网址使用右侧抽屉，共用同一套表单字段。
5. 分类管理使用独立抽屉，支持新增一级分类、新增子分类、重命名和删除。
6. 删除网址和分类前必须二次确认。
7. 小屏幕下分类导航收进抽屉，网址列表改为纵向布局。

## 三、技术方案

1. 在 `fronted/src/api/web` 中集中定义网站模块 API 类及相关类型。
2. 页面只调用 `webApi`，不直接使用 Axios 或拼接接口地址。
3. 复用 Ant Design 的 `Tree`、`Drawer`、`Form`、`Dropdown`、`Pagination`、`Empty` 和 `Skeleton`。
4. JSON 导出由前端分页读取全部网址和分类，生成带版本号及导出时间的 JSON 文件。
5. 路由路径使用 `/web`，页面注册名使用 `webRetention`。

## 四、接口与数据

- `GET /web/categories`：读取分类树。
- `POST /web/categories`：新增分类。
- `PUT /web/categories/{id}`：重命名或调整分类。
- `DELETE /web/categories/{id}`：删除空分类。
- `GET /web/list`：分页读取网址，可按分类或全部范围查询。
- `POST /web/list`：新增网址。
- `PUT /web/list/{id}`：编辑网址。
- `DELETE /web/list/{id}`：删除网址。

## 五、开发顺序

1. 补充网站模块 API 类型和 API 类。
2. 实现分类导航、网址列表和分页。
3. 实现网址新增、编辑、删除。
4. 实现分类管理和 JSON 导出。
5. 接入路由、导航和响应式样式。

## 六、检查方式

1. 执行前端 TypeScript 与语法检查，不执行完整构建。
2. 检查页面不直接导入 Axios。
3. 检查桌面端和小屏幕布局不会产生页面级横向滚动。
4. 检查加载、空数据、请求失败和提交中状态均有明确反馈。

## 七、验收步骤

1. 进入 `/web` 后默认看到全部网址。
2. 点击未分类或任一分类后，列表按对应范围刷新并回到第一页。
3. 能新增、编辑、删除网址，并在操作完成后刷新列表。
4. 能新增一级或二级分类、重命名分类及删除空分类。
5. 能导出包含 `version`、`exportedAt`、`categories` 和 `bookmarks` 的 JSON 文件。
6. 小屏幕下能通过分类按钮打开分类导航，并正常完成主要操作。
